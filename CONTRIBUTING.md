# Contributing to WristBlocks

Thanks for helping. The most valuable things right now:

1. **Testing on real watches** (Apple Watch especially) and reporting what you see.
2. **New blocks** that work on both Apple Watch and Wear OS.
3. **Tests** for the validator and the two runtimes.

## Report a device test

Open an issue with the **Device test** template. Include the watch model, OS version, which app file you used, what worked and what didn't, and a photo or screenshot if you can.

## Repo map

| Path | What |
|---|---|
| `apps/` | App files, one per app (`<id>.json`). Each one is built for both watches. |
| `tools/validate.py` | Checks app files. Runs before every build. `python3 tools/validate.py --selftest` |
| `runtime/apple/` | SwiftUI runtime for Apple Watch (`App/WristApp.swift`), Xcode project generated by XcodeGen from `project.yml`. |
| `runtime/wearos/` | Kotlin runtime for Wear OS (`app/src/main/java/.../MainActivity.kt`). |
| `editor/index.html` | The blocks editor, one static page (Blockly). |
| `docker/` | The local build box. |
| `.github/workflows/` | Builds for both watches, publishes releases, deploys the editor. |

## Add a block

A block must exist in **four** places, in this order:

1. `tools/validate.py`: add its fields to `BLOCK_FIELDS` and its rules in `validate()`, plus a good and a bad case in `_selftest()`.
2. `runtime/apple/App/WristApp.swift`: draw it in `BlockView`.
3. `runtime/wearos/.../MainActivity.kt`: draw it in `BlockView`.
4. `editor/index.html`: define it in `defineBlocksWithJsonArray`, read it in `toSpec()`, preview it in `render()`.

Then add or update an example in `apps/` so CI builds it on both watches.

## Run things locally

```bash
python3 tools/validate.py --selftest                 # validator tests
python3 -m http.server 8090 --directory editor       # editor on http://localhost:8090
cd runtime/wearos && ./gradlew assembleRelease -PappJson=../../apps/tally.json   # Wear OS (JDK 17 + Android SDK 37)
```

Apple Watch on a Mac: see [docs/install-apple-watch.md](docs/install-apple-watch.md), route A.

## Pull requests

- Keep each PR to one change. CI must pass: it validates every app file and builds both watches.
- Pull requests from forks run with read-only permissions and never publish releases.
- **Never commit or paste** Apple IDs, passwords, signing certificates (`.p12`, `.mobileprovision`), API keys or personal data. Secret scanning and push protection are on and will block pushes that contain keys.
- Local AI agent or plugin state (`.claude*`, `.swarm/`, `*.db`) is ignored on purpose; don't force-add it.
